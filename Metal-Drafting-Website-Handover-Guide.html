1. Project overview

The website source code lives on the main branch. The live public site is served from a separate branch called gh-pages (built production files only).

ItemDetails
Source branch main — all editable Angular source code
Deploy branch gh-pages — auto-generated build output for GitHub Pages
Live URL https://metaldrafting.com
GitHub repo github.com/metaldrafting/mdraft-website
Local preview http://localhost:4200 after running npm start
Important: Do not manually edit files on the gh-pages branch. Always edit source on main, then run the deploy script.

2. What you need installed

Install these once on the computer that will maintain the website:

  1. Git — https://git-scm.com/downloads
  2. Node.js LTS (v20 or newer recommended) — https://nodejs.org/
    This also installs npm.
  3. A code editor (recommended: VS Code / Cursor)
  4. Access to the GitHub account that owns metaldrafting/mdraft-website (or a collaborator account with write access)

Verify installation in Terminal / Command Prompt:

git --version
node --version
npm --version

3. GitHub access & authentication

GitHub no longer accepts your normal account password for Git push/pull over HTTPS. You must use a Personal Access Token (PAT).

3.1 Create a Personal Access Token

  1. Sign in to GitHub as the account that can write to this repository.
  2. Go to Settings → Developer settings → Personal access tokens.
  3. Prefer a Fine-grained token:
    • Resource owner: metaldrafting
    • Repository access: only mdraft-website
    • Permissions → Contents: Read and write (required for push/deploy)
    • Metadata: Read-only
  4. Generate the token and copy it immediately (shown only once).
Security: Treat the token like a password. Do not paste it into chat, email, or commit it into the repository.

3.2 When Git asks for credentials

  • Username: your GitHub username (e.g. metaldrafting)
  • Password: paste the PAT (not your GitHub login password)

On macOS, credentials are usually saved in Keychain after the first successful login.

4. Clone the repository (first time)

Open Terminal, go to the folder where you want the project, then run:

cd ~/Documents
git clone https://github.com/metaldrafting/mdraft-website.git
cd mdraft-website

If authentication is required, use the username + PAT as described above.

After cloning, you should see files like package.json, angular.json, src/, and deploy-gh-pages.sh.

5. Install dependencies & run locally

Always run these commands from the project root (the folder that contains package.json).

# Install packages (first time, or after package.json changes)
npm install

# Start local development server
npm start

Browser should open http://localhost:4200. Leave this running while you edit; the page refreshes when you save files.

Optional — share the local preview on your Wi‑Fi network (phones/other PCs):

npm run start:lan

Then open the Network URL shown in the terminal (example: http://192.168.x.x:4200).

Stop the server with Ctrl + C.

7. Git workflow: pull → change → commit → push

Use this flow every time you update the site.

Step A — Get the latest code

cd mdraft-website
git checkout main
git pull origin main

Step B — Make your edits

Edit files in your editor, then check locally with npm start.

Step C — See what changed

git status
git diff

Step D — Stage and commit

# Stage specific files
git add src/app/pages/home/home.html src/app/pages/home/home.scss

# Or stage everything modified (be careful)
git add -A

# Create a commit with a clear message
git commit -m "Update contact address on home page"
Write short, clear commit messages describing what changed (example: “Fix footer spacing”, “Update project images”).

Step E — Push source to GitHub

git push origin main

This uploads source code to GitHub. It does not automatically update the live website. You still need the deploy step below.

Useful Git commands

# Current branch and changed files
git status

# Commit history
git log --oneline -10

# Undo unstaged local edits in one file (careful: discards changes)
git checkout -- src/app/pages/home/home.html

# Discard all uncommitted local changes (careful!)
git reset --hard
git clean -fd

8. Deploy to the live website

Deployment builds the production site and force-updates the gh-pages branch. The deploy script also writes the custom domain CNAME for metaldrafting.com.

Deploy command

cd mdraft-website

# Make sure latest source is committed & pushed first
git status
git push origin main

# Build + publish to GitHub Pages
./deploy-gh-pages.sh

# Equivalent npm script:
# npm run deploy

What the script does:

  1. Builds Angular in production mode with base-href=/ (needed for custom domain root)
  2. Copies index.html to 404.html (helps SPA routing on GitHub Pages)
  3. Writes CNAME containing metaldrafting.com
  4. Pushes the built files to branch gh-pages
After a successful deploy, wait 1–2 minutes, then hard-refresh the live site:
https://metaldrafting.com
On Mac: Cmd + Shift + R  |  On Windows: Ctrl + F5
On macOS/Linux, if the script is not executable, run once:
chmod +x deploy-gh-pages.sh

9. GitHub Pages settings (already configured)

These should already be set. Check only if the live site stops working:

  1. Open Repo → Settings → Pages
  2. Source: Deploy from a branch
  3. Branch: gh-pages / /(root)
  4. Custom domain: metaldrafting.com (DNS check successful)
  5. Enforce HTTPS: enabled
Do not change base-href to /mdraft-website/ while using the custom domain metaldrafting.com. Root domain requires base-href=/ (already handled by deploy-gh-pages.sh).

12. Troubleshooting

ProblemWhat to do
Invalid username or token / password not supported Use a Personal Access Token as the password. Create/regenerate PAT with Contents: Read and write.
Permission ... denied / HTTP 403 on push Token lacks write permission, or account is not a collaborator/owner. Fix PAT scopes or repo access.
Site blank / JS & CSS 404 on live domain Redeploy with ./deploy-gh-pages.sh (must use base-href=/ for custom domain). Hard-refresh browser.
Local site won’t start Run npm install again. Confirm Node.js is installed. Check you are in the project root.
Changes pushed but live site unchanged You pushed main only. Run deploy script to update gh-pages. Wait 1–2 minutes + hard refresh.
macOS: old credentials cached Open Keychain Access → search github.com → delete old internet password entries → push again and enter new PAT.

Clear macOS cached GitHub credentials (optional)

printf "protocol=https\nhost=github.com\npath=metaldrafting/mdraft-website.git\nusername=metaldrafting\n\n" | git credential-osxkeychain erase

Then run git pull or git push again and enter the new PAT when prompted.
